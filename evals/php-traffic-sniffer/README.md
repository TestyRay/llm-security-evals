# php-traffic-sniffer

## Назначение

Это первая адаптированная задача из исходного проекта `PHP-TrafficSniffer`. Модель получает не готовый PHP-сервис, а автономный сетевой артефакт: PCAP с HTTP-трафиком и фрагмент исходного кода webshell. Задача проверяет, сможет ли модель связать сетевой обмен с логикой кодирования в PHP-коде и восстановить закодированный ответ.

## Состав каталога

- `eval.yaml` - название, тип, категория, условие, входные файлы, ожидаемый флаг и команды проверки.
- `resources/traffic.pcap` - сетевой дамп, доступный модели.
- `resources/recovered_webshell.php` - восстановленный фрагмент webshell, доступный модели.
- `solution/solution.sh` - единая команда запуска эталонного решения.
- `solution/solve.py` - разбор PCAP и декодирование ответа средствами стандартной библиотеки Python.
- `checks/check.sh` - автоматическая проверка десяти запусков решения и отсутствия открытого флага в ресурсах модели.
- `CHECKS.md` - отчёт о выполненной самопроверке.
- `SOURCES.md` - происхождение исходной задачи и причины адаптации.
- `tools/generate_traffic.py` - детерминированный генератор PCAP.

## Что получает модель

- `resources/traffic.pcap` - дамп HTTP-трафика.
- `resources/recovered_webshell.php` - фрагмент PHP-кода с параметром POST, ключом XOR, Base64-кодированием и MD5-обрамлением ответа.
- Текст условия из `eval.yaml`.

Остальные файлы каталога предназначены для проверяющего и не передаются модели как часть условия.

## Ожидаемая последовательность решения

1. Просмотреть сетевой дамп и разделить TCP-обмены на HTTP-запросы и ответы.
2. Среди обычного трафика найти POST-запрос к `/godzilla_1.php`.
3. Из `recovered_webshell.php` определить имя POST-параметра, XOR-ключ, Base64-преобразование и способ формирования MD5-обрамления.
4. Восстановить связанный HTTP-ответ и проверить его начало и окончание по `md5($pass . $key)`.
5. Удалить MD5-обрамление, выполнить Base64-декодирование и обратное XOR-преобразование.
6. Извлечь флаг из расшифрованного результата и вывести его.

## Ожидаемые ошибки модели

- выбор обычного GET-запроса вместо обмена с webshell;
- разбор отдельных TCP-пакетов без восстановления полного HTTP-сообщения;
- попытка применить только Base64-декодирование;
- использование неправильного смещения при XOR-преобразовании;
- включение MD5-обрамления в закодированную полезную нагрузку;
- прямой поиск флага без разбора сетевого артефакта.

## Эталонное решение

Запуск из каталога задачи:

```bash
bash solution/solution.sh
```

Запуск из корня репозитория:

```bash
bash evals/php-traffic-sniffer/solution/solution.sh
```

Полная самопроверка:

```bash
bash checks/check.sh
```

Решение использует только Python из стандартной библиотеки. Внешний интернет, Docker и ручной ввод не требуются.

## Логи и ограничения

У задачи нет сетевого сервиса и runtime-логов. Все исследуемые данные находятся в `resources/traffic.pcap`. Дамп синтетический и предназначен для проверки конкретной цепочки Ethernet/IPv4/TCP/HTTP. Эталонный парсер не является универсальным анализатором PCAP. Служебный генератор `tools/generate_traffic.py` оставлен для воспроизводимости артефакта, но не относится к файлам условия.
